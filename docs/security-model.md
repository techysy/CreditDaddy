# CreditDaddy 安全模型

> 本文回答一个高频顾虑：「CD 读取本机客户端凭据做代签到，是不是凭据收割工具？」——对照代码逐层说明凭据在哪里、谁能碰、防的是谁。实现随版本演进，以 main 分支代码为准；文中标注了各防线的落库版本。

## 一句话结论

CD 的凭据**只存在你自己的机器上、只发往你自己配置的 10Router 实例**：本机解密、不往上服务端传明文、无遥测。防的是**远程拿凭据**（网络面）与**文件被拷走**（静态加密）两条路径；根本边界与一切本地工具相同——**本机被攻破（恶意软件跑在你的账户下）则全部防线失效**，这不是 CD 能解决的范畴。

## 防线清单（按攻击路径）

### 1. 存储：防文件被拷走（离线路径）

| 层 | 实现 | 版本 |
|---|---|---|
| 目录/文件权限 | 数据目录 `0700`，accounts/state/settings/zcode-net 全部 `0600`（仅当前系统用户可读） | 初版 |
| 账号凭据静态加密 | 桌面版下 `accounts.json` = AES-256-GCM 信封（文件里搜不到 token/cookie 明文）；32B 随机密钥由 safeStorage（Windows=DPAPI，绑当前系统用户）加密存 `userData/secret.key`，明文只活在内存；GCM 认证标签防篡改；`.bak` 备份同形态，不产生第二份明文 | 1.8.2 |
| 导出加密 | 导出包强制口令加密（AES + scrypt 口令推导），不可跳过；口令永不回显 | 初版 |
| 浏览器密码库 | 容器密码库独立文件，只落 safeStorage 密文；加密不可用时拒绝写入，绝不落明文 | 1.7.x |
| 历史兼容 | 明文老文件兼容读，首次保存时无缝升级为信封；CLI/NAS 无密钥来源的进程读到密文会**明示报错指路**，绝不静默清空 | 1.8.2 |

**边界说明**：DPAPI/safeStorage 把密钥绑死在当前系统用户上——「文件被拷走」（同步盘误配、电脑被物理接触、备份外泄）没有你的登录会话解不开；但恶意软件以你的身份运行时它同样能读内存，这属于系统安全范畴。

### 2. 传输：防远程/跨站拿凭据（在线路径）

| 层 | 实现 | 版本 |
|---|---|---|
| 绑定收口 | 桌面版默认只绑 `127.0.0.1`；对局域网开放是显式动作（每类网关独立开关） | 初版 |
| Host / Origin 校验 | `rejectForeignRequest`：未设密码时非回环 Host 全拒；跨站 Origin 拒绝（防 DNS rebinding 与恶意网页借浏览器 Cookie 打 API） | 初版 |
| 面板访问密码 | 设置后全部 `/api/*` 要 `x-qd-key`：scrypt 哈希存储（不存明文）、常量时间比较、错 5 次锁 5 分钟（防爆破）、只认 header（query 传密被禁，不进反代日志）；密码不回显 | 初版 |
| 壳↔daemon 会话钥 | 桌面壳用进程内随机会话钥调本机 API，重启作废，外部不可伪造 | 初版 |
| 数据面网关 | 体验包/本地补全接口：本机回环免密；局域网模式 = IP 白名单（支持 `192.168.31.*` 通配）免密直连，白名单外一律拒 | 1.6.x |
| 出站凭据 | 订阅线同步只发往**你自己配置的** 10Router 实例；免费额度线（MiMo / Meoo 等）凭据不出本机——出卡的载荷强校验**只带标量数字**，凭据永不出本机 | 1.5.x 起 |

### 3. 进程与渲染：防代码注入

- Electron 全窗口 `contextIsolation + sandbox`，渲染进程零 `nodeIntegration`，IPC 经 preload 白名单
- 登录窗 / 验证码窗使用随机一次性分区（`zcap-<uuid>`），会话互不串
- 面板响应 `Cache-Control: no-cache`——凭据永不进 HTTP 缓存
- 任意值不进敏感语义：登录分区名（persistKey）走白名单正则，`../` 等越权字符拒收（1.8.2 收紧）

### 4. 输入：防烂请求打崩守护

- 畸形请求行 400（10router#114 同款崩溃面移植）、请求体 413 限额 + JSON 防护、capture cookie 体积上限
- 1.8.2 健壮性收口：弹窗开关在飞护栏（竞态不再拽回旧状态）、IPC 调用 try/catch 兜底、空输入就地拦截（不静默开无限运行窗）

## 与「凭据收割」误伤的关系

CodeBuddy 等客户端的启发式规则会把「读取本机其他客户端凭据文件」的行为判定为收割——CD 的设计（读 WorkBuddy/Qoder/ZCode/Trae 等客户端的本地凭据做代签到）天然长得像，属于**误伤而非针对性检测**。两者的实际风险面不同：

- 官方客户端关心的是「凭据离开了它认识的进程」；CD 的凭据流是**本机 → 本机进程 → 你自己的 10Router**，全程不出用户掌控的范围
- 真正的风险主角是「本机被攻破」——那与是否使用 CD 无关，任何本地工具（包括官方客户端自己）在同一边界上
- CD 侧的应对是把防线做实：本文档列出的存储加密、传输鉴权、进程隔离三层全部可对照代码验证

## 版本备注

- 静态加密随 1.8.2 起桌面版自动启用，无开关无配置；CLI/NAS 行为不变（明文 0600，现状回退）
- 迁移与恢复：密钥文件 `secret.key` 与数据目录同生命周期，**不清理不重置**——密钥丢失 = 加密数据不可恢复，升级前无需任何操作（明文文件自动升级）

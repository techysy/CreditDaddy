### 🔧 Fixed

- **The free-quota page's "Sync to 10Router" now pushes only web-session quota cards**: the button previously triggered account-connection sync first (pushing every Qoder / WorkBuddy connection too) and then a full quota-card push (even dragging in local-credential lines like minimax-free) — a "sync" on the web-session page silently changed unrelated things. Responsibilities are now separated: both this page's "Sync to 10Router" and "Push settings → Push now" use the `webSessionOnly` path and push only cookie-site quota cards (tokenharbor / Xiaomi MiMo / River / ModelScope / LongCat); account-connection sync belongs to the 10Router page's "Account management" dialog (with per-channel switches), and the 10Router page's push remains full-scope.
- **The "missing web session" badge clears instantly after a Qoder web-session harvest, with details refreshed proactively**: the harvest chain is three async stages (login success → Cookie harvested only after the login window closes → daemon binding), and the panel previously guessed the timing with 12s/30s setTimeouts — guess wrong and the badge stayed while the per-resource-pack details waited for a manual refresh (measured locally: login at 16:43:11, binding done at 16:43:16, badge still waiting for the periodic poll). Aligned with the existing cookie-site capture event pattern: when binding completes (bound>0) the desktop shell emits `qoder-web-session:bound`, and the panel refreshes the account list and re-queries Qoder quotas **live** (same as manual "refresh credits": a real upstream probe re-pulling per-pack details, not just hiding the badge); non-desktop contexts (no preload) still fall back to the periodic poll and the two light re-pulls after login.
- **Trae daily auto check-in failing with 9074 (issue #38, the real root cause of #31)**: the `x-device-id` used for check-in was previously **derived deterministically** from the uid, but the server binds "account ↔ device" to **the one registered at login** — from the day after import the derived unknown device id was persistently rejected by risk control ("too many participants, try later"), and rotating other derived ids was rejected too, while manual check-in from the official client worked at the same moment. Day one succeeded only inside the risk-control learning window. The check-in device id now **prefers the real device id captured from the client's `storage.json` at import** (`meta.deviceId`); derived ids only serve as fallback when no real id exists (pure token import) or during 9074 retries, with the first account on a machine taking the real id and the rest deriving non-overlapping ones. After upgrading, auto check-in should recover the next day; a 9074 on day one is the risk-control window — one manual check-in from the official client clears it.

### ✨ New

- **fnOS desktop / APP via the unified gateway entry (issue #39, option 2)**: opening the fnOS desktop icon or the mobile APP from a public domain (reverse proxy / Cloudflare Tunnel etc.) showed a blank screen — the window composed `http://hostname:47860` from the current hostname, but the HTTPS entry only serves 443, unreachable (LAN worked fine). Direct `http://LAN_IP:47860` access is unaffected; if the proxy fails to start it never blocks the main service. Verified: prefix stripping / Host+Origin rewrite / complete SSE streams / POST body integrity (smoke script, all three paths).

### 🛡 Robustness hardening (2026-10-29 full audit)

A robustness audit across all 25 runtime files (concurrency / resource leaks / error paths / unbounded growth) landed the following fixes:

- **Gateways now observe "graceful disconnects" (all three)**: a client cancel before response headers (Ctrl+C / stop in the cc CLI) fires `res 'close'` but never `req 'close'` — the only abort hook previously missed it, so the whole retry loop kept running: ZCode spun the captcha solver and account rotation, Trae still created SOLO sessions and burned real credits, MiniMax ran for nothing. With the `res 'close'` hook added, cancel means stop.
- **Trae gateway no longer leaks error-response bodies**: the bodies of 401 / 429 / failed-events responses were neither read nor cancelled, pinning each connection until upstream close or the ~300s timeout — up to 5 leaked sockets per completion during a 429 storm. All are now `cancel()`ed; the session-cleanup DELETE also moved to a 10s-capped channel (a bare fetch used to hang 5 minutes on a black-holed upstream).
- **ZCode / MiniMax gateways emit an error frame on mid-stream failures**: an upstream stream break previously produced only a debug log and a silent `res.end()` — clients saw a bare EOF without `message_stop` and reported a cryptic "stream ended unexpectedly". Now one Anthropic-protocol `event: error` frame carries the reason; client-initiated disconnects still end silently.
- **Trae / MiniMax weight queries no longer block completions**: after the remaining-credits cache expired, the first request used to **serially await** every account's quota query (two POSTs per Trae account, 15s cap each) — a black-holed upstream stalled completions by 1-2 minutes with the client hanging on an already-connected SSE request. Weights are now fetched in parallel with a **2-second cap per account**: healthy upstreams still route precisely on fresh numbers; a black hole serves the previous snapshot while the refresh continues in the background for the next request. Concurrent requests share one refresh (in-flight dedupe), so the quota endpoint is not hammered per-request.
- **Proxied responses now stream**: the proxy channel used to buffer the entire body before resolving — with "proxy first" enabled, gateway completions delivered zero bytes to the client for the whole generation, guaranteeing false first-token timeouts. Now a PassThrough pipes chunks through, with the wall-clock cap still governing the streaming body (same semantics as the direct path).
- **10Router config reads no longer get silently overwritten by defaults**: any read error in `loadConfig` (transient AV/sync-tool locks, JSON corruption) used to return the default config, and the next write would persist "defaults + this change" over the real file — endpoint, key, and sync watermarks gone, plus a cleared catpaw watermark re-sending historical usage in full. Now only a missing file yields defaults; corruption recovers from `.bak` (maintained automatically before each save); other errors throw and skip the write.
- **Mutating CLI commands refuse to run beside a live daemon**: the `withAccounts` serialization only works within one process — a refreshToken the daemon's check-in tick had just rotated could be clobbered by a CLI process writing back its stale snapshot (one-time refresh dead on arrival, credential chain bricked). `add / import / checkin / remove / scan` now detect a running background instance, refuse, and point to the panel or `creditdaddy stop`.
- **Panel polling and request lifecycle**: the 30s/10s/5-min polls gained single-flight guards (no more unbounded stacking while the daemon is stuck, no thundering herd on recovery); `api()` gained a wall-clock timeout (2 min default; slow operations like full check-in runs and 10R pushes explicitly widened to 5-10 min) so half-open connections no longer wedge the polling chain; stale results from batched quota loads no longer overwrite a newer live refresh; free-pool card drag listeners bind once at startup (previously they accumulated per render, firing N reorder passes per drop); device-login polling tolerates transient failures (only 5 consecutive failures abort — a 502 from a busy daemon no longer kills the whole authorization flow).
- **Desktop shell (Electron)**: the updater's installer `spawn` gained an `error` handler (an AV-quarantined installer no longer crashes the main process with uncaughtException); `shell-open-external` only passes https URLs to the OS; the GitHub update check got a 15s timeout and the installer download a 60s idle cutoff (wall clock stays open for big files; a black hole no longer wedges the update modal); the save-password prompt switched to single-pass token substitution (a password containing a placeholder literal no longer gets corrupted before being stored); a captcha-window JSON-injection fix.
- **fnOS unified-gateway proxy**: compressed responses are no longer HTML-rewritten (decoding gzip and substituting is guaranteed garbage); a client disconnect destroys the upstream connection immediately (repeated page opens no longer accumulate parked SSE sockets); `stop` / uninstall sweep the proxy process by script name as a fallback (a lost pid file no longer leaves an orphan holding app.sock).
- **Misc**: pending Qoder web sessions now expire after 48h (stale credentials no longer sit in settings.json forever); the panel-key throttle and quota-refresh per-IP maps get periodic sweeps (public scanner sources no longer accumulate forever); catpaw usage watermarks outside the 410-day lookback window are pruned; `atomicWrite` cleans up its half-written temp file when the first write fails; deleting an account clears its cooling/weight/sticky residue in all three gateways (`forgetAccount`); Qoder reports a clear error on "200 but not JSON" responses (no more SyntaxError masquerading as "token unavailable" and prompting needless re-imports); a ZCode manual claim pass re-arms the auto-claim scheduler if auto-claim was enabled meanwhile (it used to die silently); the settings endpoint no longer skips a same-request password change because check-in fields early-returned; dead code cleanup in the Doubao client.

## [1.6.2] (2026-10-26)

Theme: **ZCode pack gateway dispatch hardening (rotation fix + session stickiness) + LongCat pack-row number fix + claim arrival time surfaced + 429 backoff ladders and switch/claim feedback hardening**.

> **Added before tagging (2026-10-28)**: the four groups below — 429 backoff ladders, WorkBuddy not-installed guard, instant claim feedback, and 10Router per-channel sync switches — ship with this release (the tag had not been published, so no separate version number was needed).

### 🔧 Fixed

- **Gateway 429 cooldown: fixed 5 minutes → escalating backoff ladder**: all three gateways (ZCode / MiniMax / Trae) hardcoded a 5-minute cooldown on 429 — upstream rate-limit windows usually outlast it, so each account looped "cooldown expires → immediately 429 again" (the log showed nothing but "cooling 5 minutes"). Now the cooldown follows a ladder by consecutive count: **30s → 1min → 2min → 5min → 10min** (capped at 10 minutes from the 5th consecutive 429), and one successful completion resets the count — an occasional 429 never accumulates; only genuinely throttled accounts see longer waits. Resets cover both completion paths (streaming / JSON), credential-refresh revival, gateway re-enable, and a fresh claim; the log now carries the streak ("cooling 10 min, consecutive #2"), making one-off vs. sustained throttling obvious at a glance.
- **Trae gateway: 429 during the events phase didn't count**: Trae completions are two-phase (create session → read the events stream); a 429 on the stream only logged "events HTTP 429" without counting, so the next request still started from the 30-second rung and crashed into the window again. It now follows the same ladder as session creation.
- **WorkBuddy: switching without the client installed now says so clearly**: `writeWorkbuddySession()` used to mkdir + write the session file unconditionally and report success — on machines without the WorkBuddy / CodeBuddy client the panel showed "switched" while no client would ever apply those credentials, a pure dead end. New `detectWorkbuddy()` only trusts the client executable (the credentials directory is not evidence — the empty shell CD itself mkdirs would false-positive), the switch endpoint returns `WORKBUDDY_NOT_INSTALLED`, the panel toasts guidance on click and the WorkBuddy page shows a banner when not installed (token import / quota / daily claiming are unaffected; only switching needs the client).
- **ZCode claim results now land on the card instantly**: both claim paths (background auto-claim and the manual dialog) only reloaded quotas without re-rendering, leaving the card stale; and `statusOf()` returned an empty badge for ZCode, so the claim result left no trace at all. Activity grants usually carry an `effective_at` later the same day — until then the quota row shows "pending", indistinguishable from "nothing happened" to the user, whose only recourse was a manual refresh. All three triggers (auto-claim / manual dialog / per-card refresh) now re-render, and ZCode got "Claimed / Already claimed / Claim failed" badges.
- **ZCode pack gateway "multi-account rotation" never actually rotated — every request piled onto the first account**: `rotationQueue()` normalized the rotation pointer `rrIndex` into range but **never incremented it**, so the queue head was always the first account in the store and `handleGateway` started every request there; other accounts only got traffic when it failed / cooled / died. The pointer now advances one step per request, spreading load across accounts; when the ready-set changes the start re-normalizes instead of walking out of bounds. The sibling MiniMax gateway's "sticky primary + weight sort" always dispatched; ZCode's pointer never turned at all — an implementation defect unique to that line.
- **LongCat pack rows reported distorted numbers (issue #37)**: rows pushed to 10Router embedded the real numbers in the `name` text ("3.1757M / 5M · 36% consumed") while the structured fields carried `used=0 / total=remaining / remainingPercentage=100` — 10R's renderer only trusts structured fields, so cards drew a full unused bar contradicting the label. Now **fields are the truth**: `used` = consumed, `total` = pack total, `remainingPercentage` = remaining %, `name` is a plain label again ("Bonus pack" / "Resource pack"), expiry rides `resetAt`; the Balance summary row pushes Σconsumed / Σtotal so 10R can draw the consumed segment (it previously pushed remaining as total, leaving the bar always full).
- **ZCode claim that lands later now says when ("HH:MM arrival")**: `claimPlan()` always returned `startsAt`, but `zcodeAutoClaim` dropped it — `claims` carried only plan/via/ok. Symptom: the auto-claim log said "claimed (no captcha) — 300M ZCODE GLOBAL BUILD tokens" while the panel only showed "pending 300M · arrives 23:00", leaving users unsure whether the claim had actually taken. Both claim paths (no-captcha / silent-captcha) now carry `startsAt` and append "（arrives HH:MM）" only while the arrival time is still in the future (time-only for same-day, date+time across days).

### ✨ New

- **ZCode pack gateway session stickiness**: consecutive turns of the same conversation pin to the same account; only a new session rotates (hopping accounts fragments context). The session id comes from the caller's `metadata.user_id` (tolerant parsing of nested JSON string / bare top-level fields / raw string), and `metadata.user_id` is now **passed through verbatim when provided, generated only when absent** — previously every request minted a fresh `session_id`, so from the upstream's view every request was a new conversation and continuity was broken by design. Stickiness TTL 30 minutes before yielding to rotation; a pinned account that gets blocked / cooled / marked yields automatically instead of sticking. Callers without `metadata` degrade to pure rotation (safe).
- **10Router per-channel sync switches**: the Account Management dialog gains a channel checklist (only channels with accounts on this machine), each with two boxes — the main box = quota-card push, "conn" = account-connection sync. When 10Router already has a same-source channel configured (e.g. a minimax-code connection), unticking here drops CD's duplicate free card (`minimax-free-*`) — previously both cards existed with independently refreshing numbers. `tenrouter.json` gains `accountSync { enabled, providers }` (empty providers = all channels, backward compatible) and `quotaPushDisabledProviders[]`; refresh callbacks for excluded channels return 410 and stop going upstream. Cards already on 10Router are not deleted by CD (avoiding removal of hand-made cards) — they age out over the 7-day TTL or can be deleted manually.
- The "In use by API" badge now notes rotation sharing when multiple ZCode accounts exist (n accounts, one per request), so a single account doesn't look like the only servant; `gatewayStatus` exposes `stickySessions`.

### 🌐 Other

- All three gateways' `gatewayStatus` gained `coolingDetail` (remaining seconds / text / streak); the `cooling` field keeps its historical string-array shape.
- New `formatDuration.js`: human-readable durations — 30s displays as "30 s" (rounding ms→minutes would render it as "1 minute").
- 10Router toolbar order is now Refresh · Usage sync · Account management · Settings.
- Test hardening: per-rung ladder assertions + cap + reset-on-success for all three gateways, `formatDuration` boundaries, `detectWorkbuddy` decisions, channel allow-list filtering / excluded-channel zero-push (key cases verified to fail with the fix removed); 340 tests total.
- i18n entries for the cooldown ladder / WorkBuddy guidance / channel switches, synced across four languages; `scripts/check-i18n.js` full coverage passes.
